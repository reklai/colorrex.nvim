*colorrex.txt*  Compile your terminal's theme into a native colorscheme

INTRODUCTION                                                        *colorrex*

colorrex reads the colors your terminal reports and compiles them into a
native Neovim colorscheme. It has no dependencies and needs no configuration.
>lua
    vim.cmd.colorscheme("colorrex")
<
With lazy.nvim, installing it is enough: `{ "reklai/colorrex.nvim" }`

Requires Neovim 0.12 or newer and a libghostty terminal, such as Ghostty or
Rex, and works through tmux with no setup; see |colorrex-tmux|. herdr, a
multiplexer built on libghostty, should work too, but is not yet tested. If the terminal reports no
colors, colorrex stays grey and says so once at startup.

colorrex is young, so expect bugs and edge cases nobody has hit yet. If
something looks wrong, please report it with the output of |:ColorRex| status.

MEANINGS                                                   *colorrex-meanings*

One meaning wears one color in every language, with nothing to configure.
Whatever color the theme gives nil, everything that can fail or be missing
wears it, and nothing else does: nil, null, None, undefined, err, Err, error
types, throw, raise, catch, rescue, panic, errdefer, orelse, and Rust's ?.
Numbers and booleans are values, in the string's family. Diagnostic severity
also shows in the underline: a curl for an error, dashes for a warning, dots
for the rest.

Any language with a Tree-sitter highlights query is covered by the capture
names grammars share. A short list of words that mean the same thing across
languages adds failure where a grammar marks one as a name, a constant, a type
or a call. Negation is on it too: `!` as a prefix, `not` and `unless` take the
keyword color in bold. Tested against the grammars of C, C++, C#, Elixir,
Erlang, Gleam, Go, Haskell, Java, JavaScript, Kotlin, Lua, Odin, PHP, Python,
Ruby, Rust, Swift, TSX, TypeScript and Zig.

TMUX AND HERDR                                                 *colorrex-tmux*

A herdr pane runs libghostty itself, so from its source it answers the same
one-request read as the terminal; this is not yet tested in a real herdr. tmux drops that request unless allow-passthrough is on, so
colorrex asks one question per color instead, which tmux answers. tmux never
reports the cursor color; colorrex takes it from the last time this machine
saw the same sixteen colors whole.

Dark/light changes arrive at once. Other changes show when you pause typing:
colorrex asks once then, at most every two seconds. For the whole theme in one
read, add to tmux.conf: >
    set -g allow-passthrough on
<

PROMISES                                                   *colorrex-promises*

There are three. They are goals, and each one is tested.
|:ColorRex| check judges the current theme against them, and every adjustment
it lists is named after the promise it serves.

faithful        Your foreground and background are never altered, and every
                syntax color is one of your theme's ANSI colors. A color too
                faint to read moves in lightness only, the minimum needed.
                Code stays readable on what is behind it: a selection,
                reference, snippet placeholder or float eases off for it.

practical       Color goes where it tells you something the shape of the text
                does not. Fields, methods and variables differ, every pair of
                syntax roles can be told apart, and `=` and `self` stay quiet.

voice           Every theme should look like itself. A cursor with a color of its own
                takes the keywords, a difference you can see shows, and a
                family of themes stays a family.

COMMANDS                                                           *:ColorRex*

:ColorRex               Read the terminal's theme and repaint if it changed.
                        Run this after changing to a theme of the same
                        brightness in Rex, which sends no signal for that.
                        Every other Neovim on this machine then checks its own
                        terminal too.

:ColorRex status        Show the active theme and the last sync.

:ColorRex explain [group]
                        Show where a highlight group's color came from. With
                        no group, uses the one under the cursor.

:ColorRex check         Judge the current theme against |colorrex-promises|,
                        and list every adjustment that was needed.

:ColorRex[!] compile [name]
                        Write the current theme to colors/{name}.lua in your
                        config, as a standalone colorscheme that needs no
                        plugin. {name} defaults to "colorrex-static". Use ! to
                        replace an existing file.

MAPPINGS                                                   *colorrex-mappings*

Nothing is mapped by default. Each of these runs the same code as the command:

    <Plug>(colorrex)
    <Plug>(colorrex-status)
    <Plug>(colorrex-explain)
    <Plug>(colorrex-check)
>lua
    vim.keymap.set("n", "<leader>ts", "<Plug>(colorrex)")
<
OPTIONS                                                     *colorrex-options*

All optional. Pass them as `opts` in a lazy.nvim spec, or call `setup()`, which
also turns the colorscheme on.
>lua
    require("colorrex").setup({
      transparent = true,
      contrast = 3.0,
      voice = true,
      chunks = false,
      auto = true,
    })
<
transparent     Leave the background to the terminal, so its exact color and
                any opacity show through.

contrast        Minimum contrast for code against the background, from 1 to
                4.5. Colors below it move in lightness only. Text that a group
                paints on its own fill, such as in a float, meets it too.

voice           Give each theme its own voice. A cursor with a color of its
                own decides which of six arrangements the theme uses, and that
                color takes the keywords. Colors stay the theme's and themes
                meant as a set stay together, but themes with nearly identical
                palettes and cursors stay alike. A theme whose cursor is not a
                color of its own is unchanged, which is most themes with a look
                known from elsewhere. When false, roles always follow the ANSI
                convention and move only to keep code readable. Renamed from
                `force_unique`, which now raises an error naming it.

chunks          Mark where each chunk of code starts. The name on its first
                line stands out, so a file can be scanned by its shape. A chunk
                is any named thing of five lines or more in the outer two
                levels, found from the Treesitter tree in any language. It
                needs Treesitter highlighting in the buffer and looks only at
                the lines on screen. These names take the cursor color, or the
                function color if the cursor is nearest red or has no color of
                its own.

auto            Also sync on focus and on dark or light changes, and when
                another Neovim on this machine saves a new theme. While focus
                is elsewhere, as it is while Rex's theme picker is open, also
                ask the terminal for changes: every 30ms, every 250ms after 5
                seconds with no change, and not at all after a minute with
                none. When false, colors change only through |:ColorRex|.

LUALINE                                                     *colorrex-lualine*

Set `theme = "colorrex"`. It follows every sync, and lualine is not a dependency.
